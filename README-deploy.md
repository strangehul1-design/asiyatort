# Как развернуть сайт «Торт по любви»

Сайт — обычная статика: HTML, CSS и JS без сборщика. Ставится на любой
хостинг простым копированием файлов. Отдельно живёт серверная часть
(папка `api`) — она нужна только для автоматических уведомлений и
настоящей оплаты; без неё сайт полностью работает.

---

## Что в пакете

```
index.html            главная страница
checkout/             оформление заказа
demo-checkout/        имитация платёжного экрана (закрыта от индексации)
success/  fail/       экраны результата оплаты
assets/               стили, токены дизайна, каталог, корзина, окно ВК
robots.txt            правила для поисковых роботов
sitemap.xml           карта сайта
.nojekyll             отключает обработку Jekyll на GitHub Pages
api/                  серверная часть (Cloudflare Worker) — НЕ на хостинг сайта
.env.example          список переменных окружения без значений
```

Файлов разработки, `node_modules`, кэша и черновиков нет.
Секретных ключей нет — только `.env.example` с именами переменных.

---

## Шаг 1. Залить сайт на хостинг

Скопируйте всё, **кроме папки `api`**, в корень сайта — чтобы
`index.html` открывался по адресу `https://ваш-домен.ru/`.
Структуру папок сохраните.

Все пути внутри относительные, сайт заработает на любом домене без правок.
Проверено: ссылок на `localhost` и путей с вашего компьютера нет.

**Если хостинг принимает архив** — загрузите `site-ready-to-deploy.zip`,
распакуйте в корень и удалите оттуда папку `api`.

### Обязательно после переезда на свой домен

Замените `https://strangehul1-design.github.io/asiyatort` на свой адрес:

| Файл | Что менять |
|---|---|
| `index.html` | `canonical`, `og:url`, адреса внутри JSON-LD |
| `checkout/index.html` | `canonical` |
| `robots.txt` | строка `Sitemap:` |
| `sitemap.xml` | оба адреса `<loc>` |
| `api/wrangler.toml` | `ALLOWED_ORIGINS` |

## Шаг 2. Как сейчас приходят заявки

**Через ВКонтакте, руками клиента — сервер для этого не нужен.**

Человек заполняет форму и нажимает «Отправить заявку». Сайт собирает
текст заявки, кладёт его в буфер обмена, показывает окно
«текст скопирован» и через 6 секунд уводит в личку сообщества
**https://vk.me/asiyatort**. Клиенту остаётся вставить и отправить.

Текст всегда виден в самом окне: если браузер запретил буфер обмена
(так бывает без https), человек скопирует вручную и заявка не потеряется.

Ничего настраивать не нужно — работает сразу после заливки на хостинг.

### Куда ведут ссылки

| Где | Куда |
|---|---|
| Кнопки заявок, запасные контакты | `https://vk.me/asiyatort` (личка сообщества) |
| «Сообщество ВКонтакте» в подвале | `https://vk.ru/asiyatort` |

Чтобы поменять — правьте `VK_DM` и `VK_GROUP` в начале
`assets/vk-send.js` и ссылки в подвале `index.html`.

## Шаг 3. Автоматические уведомления (по желанию)

Если хотите, чтобы заявка приходила сама, без пересылки клиентом,
разверните серверную часть:

```bash
npm install -g wrangler
cd api
wrangler login
wrangler deploy
```

Получите адрес вида `https://tort-po-lyubvi-api.ВАШ.workers.dev`.
Впишите его в `assets/api.js`:

```js
window.API_BASE = 'https://tort-po-lyubvi-api.ВАШ.workers.dev';
```

После этого форма продолжит показывать окно ВК **и** параллельно тихо
отправит заявку на сервер — то есть заявка придёт двумя путями.

### Переменные окружения

Ни один ключ не хранится в файлах. Значение вводится в консоли:

```bash
cd api
wrangler secret put TELEGRAM_BOT_TOKEN
wrangler secret put TELEGRAM_CHAT_ID
wrangler secret put VK_TOKEN
wrangler secret put VK_PEER_ID
wrangler secret put VK_CONFIRMATION
wrangler secret put VK_SECRET
wrangler secret put YOOKASSA_SHOP_ID
wrangler secret put YOOKASSA_SECRET_KEY
```

Незаданная переменная просто выключает свой канал: без `VK_TOKEN`
заявки идут только в Telegram, без ключей ЮKassa работает демо-оплата.

Единственная не-секретная настройка — `ALLOWED_ORIGINS` в
`api/wrangler.toml`: домены, с которых принимаются заявки.

## Шаг 4. Telegram (если нужен второй канал)

1. Напишите [@BotFather](https://t.me/BotFather): `/newbot`, задайте имя
   и адрес. Придёт токен вида `1234567890:AA...`.
2. Напишите своему боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
4. Найдите `"chat":{"id":...}` — это `TELEGRAM_CHAT_ID`.

## Шаг 5. ВКонтакте через API (если нужен автоприём)

Нужно только если хотите, чтобы заявки падали в сообщество автоматически
и чтобы бот ловил входящие сообщения клиентов.

### Отправка заявок

1. Сообщество → **Управление** → **Сообщения** → включить.
2. **Управление** → **Работа с API** → **Ключи доступа** → создать ключ
   с правом **Сообщения сообщества**. Это `VK_TOKEN`.
3. `VK_PEER_ID` — ваш личный id, либо `2000000000 + id беседы`.

### Приём сообщений от клиентов

1. **Работа с API** → **Callback API**.
2. Адрес: `https://ваш-воркер.workers.dev/vk-callback`
3. VK покажет **строку подтверждения** — задайте её как `VK_CONFIRMATION`
   **до** нажатия «Подтвердить», иначе проверка не пройдёт.
4. Придумайте секретный ключ, впишите у VK и задайте как `VK_SECRET`.
5. Включите событие **Входящее сообщение** и нажмите «Подтвердить».

## Шаг 6. ЮKassa

Сейчас оплата демонстрационная: `create-payment` не ходит наружу и
возвращает ссылку на `/demo-checkout/`. Боевой режим включается сам,
как только заданы два секрета — переписывать код не нужно.

1. Зарегистрировать магазин на [yookassa.ru](https://yookassa.ru)
   (нужны ИНН и данные организации или самозанятого).
2. **Интеграция** → **Ключи API** → получить `shopId` и секретный ключ.
   Сначала **тестовые**.
3. Задать секретами `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY`.
4. **Интеграция** → **HTTP-уведомления** → адрес
   `https://ваш-воркер.workers.dev/payment-notification`,
   события `payment.succeeded` и `payment.canceled`.
5. Проверить [тестовыми картами](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing)
   (`5555 5555 5555 4444`, любой будущий срок, любой CVC).
6. Только потом заменить тестовые ключи на боевые.

### Где в коде подключается касса

`api/worker.js`, функция `handleCreatePayment` — блок помечен рамкой
`▓▓▓ НАЧАЛО БЛОКА, КОТОРЫЙ МЕНЯЕТСЯ НА БОЕВУЮ ЮKASSA ▓▓▓`.
Боевой вызов уже написан и включается по наличию ключей.

Важно: помечать заказ оплаченным можно **только** по уведомлению на
`/payment-notification`. Возврат человека на `/success` — не доказательство
оплаты: на эту страницу можно зайти вручную.

## Шаг 7. Свои товары и цены

Цена живёт в трёх местах, и это сделано намеренно:

| Файл | Роль |
|---|---|
| `api/catalog.js` | **главный.** По нему считается сумма платежа |
| `assets/catalog.js` | название и цена для корзины |
| `index.html`, блок `.prices` | то, что видит человек и поисковик |

Сумму заказа считает **только** сервер. Всё, что пришло из браузера,
кроме `id` и количества, игнорируется — подменить цену в запросе нельзя.
При добавлении позиции обязательно пропишите её в `api/catalog.js`
с тем же `id`, иначе заказ отклонится.

Сверить цены сервера: `https://ваш-воркер.workers.dev/catalog`

## Шаг 8. Домен и https

* Включите бесплатный сертификат (обычно Let's Encrypt).
* Настройте редирект `http://` → `https://` и один вариант из
  `www` / без `www`. Иначе поисковик сочтёт это разными сайтами.
* На GitHub Pages https включается галочкой **Enforce HTTPS**,
  вариант с `www` — через CNAME у регистратора.

---

## Что заменить перед запуском

Контакты, адрес студии, отзывы и цены ярусов — **демонстрационные**.
Замените на настоящие, особенно в блоке JSON-LD в `index.html`:
вымышленные данные в структурированной разметке поисковики считают
обманом и понижают сайт.

Файлы с контактами: `index.html` (подвал и JSON-LD),
`checkout/index.html`, `success/index.html`, `fail/index.html`.
