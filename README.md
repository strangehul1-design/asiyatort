# Торт по любви — лендинг кондитерской

Одностраничный сайт кондитерской, специализирующейся на свадебных тортах.
Один файл `index.html` — без сборки, зависимостей и внешних скриптов.

## Что внутри

- **Три режима в одном блоке** — «Заказать торт», «Дегустация», «Доставка»
  переключаются кнопками, панель открывается под ними.
- **Форма заказа** — дата, площадка, число гостей, загрузка фото-референса,
  выбор начинки, презентация и нарезка, способ и время связи.
- **Короткая форма дегустации** — дата, количество человек, контакты.
- **Самодорисовывающийся эскиз** — линейный SVG торта: ярусы появляются
  по мере прокрутки шагов заказа.
- **Слоты под фотографии** держат пропорции будущих снимков, чтобы макет
  не поехал при замене на реальные кадры.

## Оформление

| | |
|---|---|
| Фон | айвори `#FBF9F5`, ракушка `#F4EDE7` |
| Текст | графит `#2E2A27`, абзацы `#544D47`, подписи `#6E675F` |
| Акцент | пудровая роза `#915B4A`, шампань `#9C8558` |
| Заголовки | Cormorant Garamond |
| Текст | Jost |

Контраст всех текстовых пар проверен по WCAG AA (минимум 4.5:1 для обычного
текста, 3:1 для крупного и иконок).

## Анимации

Скролл — инерционный лерп на десктопе с мышью; полоса прогресса; появление
блоков и шторки по IntersectionObserver; построчный выезд заголовков из-под
маски; дрейф карточек; параллакс героя. Кнопки — заливка снизу вверх,
магнитное притяжение к курсору, отклик на нажатие, сдвиг стрелки.

Всё это выключается при `prefers-reduced-motion: reduce`; магнитные кнопки
не включаются на тач-устройствах.

## Как открыть

Скачайте `index.html` и откройте в браузере — сборка не нужна.

## Структура

```
index.html            главная: работы, процесс, цены, формы, отзывы
checkout/             оформление заказа

```

## Магазин и оплата

Корзина хранит **только id и количество**. Сумму считает сервер по
`api/catalog.js` — всё, что пришло из браузера сверх этого, игнорируется.
Подменить цену в запросе нельзя.

Оплата пока демонстрационная: `create-payment` не ходит наружу, а
возвращает ссылку на `/demo-checkout/`. Схема повторяет ЮKassa один в один,
боевой режим включается сам при появлении секретов `YOOKASSA_SHOP_ID` и
`YOOKASSA_SECRET_KEY` — переписывать флоу не нужно.

## Заявки в Telegram

Заявка приходит в Telegram сама, как только клиент нажал кнопку.

Порядок такой:

1. Клиент отправляет форму.
2. Заявка **сразу записывается в хранилище** — до попытки отправки.
3. Потом уходит в Telegram: текст, следом фото-референсы.
4. Telegram не ответил — заявка остаётся в хранилище и **дошлётся
   автоматически** со следующей заявкой. Телефон клиента не теряется.
5. Недоступен и сам посредник — сайт покажет окно с текстом и предложит
   отправить в сообщество ВКонтакте. Ложного «отправлено» клиент не
   увидит никогда.

| Маршрут | Что делает |
|---|---|
| `POST /submit` | заявки с форм сайта |
| `POST /create-payment` | считает сумму, создаёт платёж |
| `POST /payment-notification` | вебхук ЮKassa о статусе |
| `ANY /vk-callback` | подтверждение и входящие из VK |
| `GET /catalog` | цены, которыми считает сервер |
| `GET /pending?key=…` | заявки, которые не дошли |
| `GET /requests?key=…` | все заявки за полгода |

Без правильного `ADMIN_KEY` последние два адреса отвечают «не найдено» —
чужой не подберёт их и не увидит телефоны клиентов.

### Шаг 1. Создать бота

1. Найдите в Telegram **@BotFather** (с синей галочкой), нажмите «Запустить».
2. Отправьте `/newbot`.
3. Он спросит **имя** — подпись, видная в переписке. Например:
   `Торт по любви — заявки`
4. Потом **логин** — латиницей, обязательно заканчивается на `bot`.
   Например: `tort_po_lyubvi_zayavki_bot`. Занят — придумайте другой.
5. Придёт строка вида `1234567890:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw`.
   Это **токен**. Никому не показывайте и в файлы сайта не вставляйте —
   он даёт полный доступ к боту.

### Шаг 2. Узнать номер чата

Бот не может написать первым — сначала напишите ему вы.

1. Найдите бота по логину, нажмите «Запустить», отправьте «привет».
2. Откройте в браузере, подставив токен:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
3. Найдите `"chat":{"id":123456789` — число после `id` это **chat_id**.

Для общего доступа: создайте группу, добавьте бота, напишите туда
сообщение и повторите шаг 2. Номер группы будет с минусом — минус нужен.

### Шаг 3. Проверить бота

Откройте в браузере:

```
https://api.telegram.org/bot<ТОКЕН>/sendMessage?chat_id=<CHAT_ID>&text=проверка
```

Пришло «проверка» — бот настроен. Ошибка `chat not found` — вы не
написали боту первым.

### Шаг 4. Запустить посредника

Нужен бесплатный аккаунт на [dash.cloudflare.com](https://dash.cloudflare.com).

```bash
npm install -g wrangler
cd api
wrangler login
wrangler kv namespace create REQUESTS
```

Последняя команда напечатает `id = "..."`. Вставьте это значение в
`api/wrangler.toml` вместо `ЗАМЕНИТЕ_НА_ID`.

Ключи — в закрытое хранилище. Каждая команда спросит значение, вставьте
и нажмите Enter; на экране оно не останется:

```bash
wrangler secret put TELEGRAM_BOT_TOKEN
wrangler secret put TELEGRAM_CHAT_ID
wrangler secret put ADMIN_KEY
```

`ADMIN_KEY` придумываете сами — это пароль для просмотра заявок.

```bash
wrangler deploy
```

Команда напечатает адрес вида
`https://tort-po-lyubvi-api.ваш-логин.workers.dev`. Скопируйте его.

### Шаг 5. Связать сайт с посредником

В файле `assets/api.js` вставьте адрес в кавычки:

```js
window.API_BASE = 'https://tort-po-lyubvi-api.ваш-логин.workers.dev';
```

Сохраните, залейте на хостинг. Заявки пойдут в Telegram.

### Проверка без настоящего Telegram

В папке `api` лежит сквозной тест: поднимает поддельный Telegram,
прогоняет настоящие заявки и проверяет 31 условие — подписи полей,
разные заголовки форм, отправку фото, поведение при сбое, досылку
недоставленного и защиту от спама.

В трёх окнах терминала:

```bash
node api/fake-telegram.js 8787
npx wrangler dev --config api/wrangler.dev.toml --port 8788 --local
node api/e2e-test.js
```

Файл `api/wrangler.dev.toml` создаётся копией `wrangler.toml` с
подменёнными `TELEGRAM_API_BASE = "http://localhost:8787"` и тестовым
токеном — настоящие ключи для теста не нужны.

## Редактор сайта в том же боте

Тот же бот, что приносит заявки, умеет менять содержимое сайта. Открываете
переписку, отправляете `/start` — и дальше по кнопкам. Правки видны на
сайте сразу, перезаливать ничего не нужно.

### Что можно менять

| Раздел | Что именно |
|---|---|
| 📞 Контакты | телефон, почта, адрес студии, часы, зона доставки, ссылки на сообщество |
| 💰 Цены | название, описание, цена и примечание каждого из шести товаров |
| 💬 Отзывы | текст и подпись трёх отзывов, которые уже стоят на сайте |
| 🖼 Фотографии | 14 слотов: главное фото, работы, доставка, галерея |
| 📝 Тексты | абзац первого экрана, подписи к разделам, описание дегустации |

Добавлять новые отзывы и позиции бот не умеет — только править те, что
есть. Это сделано намеренно: новые блоки меняют вёрстку, а правка текста
нет.

### Как это устроено

Исходные тексты остаются прямо в HTML. Бот записывает только изменения
поверх них, а сайт при загрузке их подставляет. Отсюда три следствия:

- воркер недоступен — сайт покажет исходный текст, а не пустые места;
- поисковики видят настоящее содержимое, а не заглушки;
- кнопка «Вернуть как было» просто убирает правку.

Цена — особый случай. Правка через бота меняет и карточку, и корзину,
**и сумму при оплате**: считает всегда сервер, поэтому показанное и
списанное не разойдутся.

### Подключение

Нужно один раз сказать Telegram, куда слать нажатия кнопок.

**Шаг 1.** Придумайте пароль для связи с Telegram (любой набор латинских
букв и цифр, например `hook7391secret`) и положите его в хранилище:

```bash
wrangler secret put TELEGRAM_WEBHOOK_SECRET
```

**Шаг 2.** Опубликуйте воркер заново:

```bash
wrangler deploy
```

**Шаг 3.** Откройте в браузере адрес, подставив свой токен бота и тот же
пароль из шага 1:

```
https://api.telegram.org/bot<ТОКЕН>/setWebhook?url=https://tort-po-lyubvi-api.asiyatort.workers.dev/telegram-webhook&secret_token=<ПАРОЛЬ>
```

Ответ `{"ok":true,...}` означает, что готово.

**Шаг 4.** Напишите боту `/start` — откроется меню редактора.

### Кто имеет доступ

Только владелец: бот сравнивает номер чата с `TELEGRAM_CHAT_ID`.
Посторонний, нашедший бота, увидит одну строку отказа — ни меню, ни
данных ему не покажут.

Дополнительно каждое событие от Telegram проверяется по паролю из
шага 1. Запрос без него отбрасывается с ответом «не найдено».

### Проверка без настоящего Telegram

```bash
node api/fake-telegram.js 8787
npx wrangler dev --config api/wrangler.dev.toml --port 8788 --local
node api/bot-test.js
```

Проверяет 23 условия: доступ постороннего, защиту по паролю, правку
телефона, влияние цены на оплату, проверку введённого, возврат к
исходному, отзывы и фотослоты.

## Перед публикацией

Контакты, адрес студии, цены ярусов и отзывы — демонстрационные.
Замените на настоящие, особенно в блоке JSON-LD в `index.html`:
вымышленные данные в структурированной разметке поисковики считают обманом.
